# 真实脚本任务消失问题修复（2026-11-16）

## 根因

历史轮次 `20261115-232400-445a173c` 的三个脚本任务均为 `failed / LLM_INVALID_RESPONSE`。真实 Qwen2.5-0.5B 将输入角色的 `name/description` 复制到 `sentences`，缺少 `text` 正文，因此 LLM 服务返回 HTTP 502。严格校验正确拒绝了这些结果。

前端只显示项目 `active_tasks`，并将失败写到 `console.warn`；终态任务离开 `active_tasks` 后，生成行消失且没有可见错误。该流程还依赖先观察到 active 状态，可能遗漏快速失败的任务。

## 修改

- LLM 输入改用角色分工文本及明确的合法 `role_key` 列表，将示意角色标识换成本次真实标识，避免把完整角色资料对象误当输出句子。不加入其他故事的完整示例台词，保持原文内容边界。继续严格校验 JSON、字段、角色及长度，不修补损坏结果或使用 Mock 回退。
- LLM 服务区分字段校验和角色/内容校验；生成适配器将上游具体错误传到任务；Worker 日志记录失败任务 ID 和错误码。
- 项目页查询最近脚本任务，轮询 pending 状态并在终态刷新版本。失败原因、错误码和“重新生成脚本”按钮持续显示；刷新页面后仍可读取失败记录。
- 控制台增加“重启当前服务（保留数据）”和恢复已有轮次的 `--resume`，使代码修复可以在保留项目的情况下生效。
- 增加“真实 LLM 脚本闭环（不生成音频）”，在独立测试生成库中连接当前 LLM，无须预先准备克隆录音。
