# 文字转播客 Demo 01

这是一份用于理解开发分工的最小前后端项目，不是课程完整成品。

## 先运行，不需要学完前后端

需要 Python 3.10 或以上，不需要安装 pip 依赖。

Windows：解压后双击 `start_windows.bat`。如果提示找不到 `py`，在当前目录终端运行 `python server.py`，或先安装 Python。

Mac/Linux：在解压目录运行 `python3 server.py`。

打开 http://127.0.0.1:8000 ，保留终端窗口。输入文字，选声音和风格，提交任务，播放并下载文件。关闭服务用 Ctrl+C。如果8000端口占用，运行 `python server.py --port 8001` 并访问对应地址。

**默认离线演示返回1秒WAV测试音。它不朗读正文，不区分男声女声或风格，不代表语音需求已实现。** 页面持续标明此限制。任务可能很快结束，不会人为停顿来伪造生成过程。

## 你会看见的五个步骤

1. `index.html`：网页收集正文、音色、风格、语速。
2. `POST /api/jobs`：`server.py` 检查输入，分配任务编号，返回202。
3. 后台线程调用 `providers.py`：TTS模块处理一次生成。
4. `GET /api/jobs/{id}`：网页查询排队、生成中、成功或失败。
5. `GET /api/jobs/{id}/audio`：成功后播放与下载音频。

前端处理展示；后端处理校验和任务；TTS提供者只负责把文字和设置变成音频。双方通过约定的JSON和接口路径协作。分工前先定好接口，避免各自写完后才发现接不上。

## 陈思涵的模块边界

你负责输入页面：选择TXT、读取UTF-8、粘贴编辑、标题和字数、空文或长度提示、覆盖前确认，以及向后端提交。服务端校验、数据库、LLM、TTS、后台任务、音频处理均由相应后端成员负责。服务端必须再次验证输入，不能仅信任你的页面检查。正式输入模块可拆为单独文件；本demo为了容易运行暂时集中在一个HTML中。

AI能协助生成多数代码，你需要在自己电脑验证上传中文TXT、粘贴编辑、空文、超长、错误编码、覆盖提醒和提交失败。通过这些操作理解“这个按钮发送什么、成功后得到什么、失败后怎么办”，足以开始做个人模块。

## 新提出的播客脚本流程

原需求基线是“确认原文→TTS”；新设想是“原文→LLM播客脚本→用户审核编辑→TTS”。两者应由小组确认后选定，不能在文档中悄悄混用。

如果引入脚本生成，先用单人讲解，并分两次提交：

1. 输入页提交原文，后端建立脚本生成任务；LLM返回后展示可编辑脚本。
2. 用户确认脚本，提交音色风格；后端建立音频任务，TTS返回音频后播放下载。

任务字段建议包括：task_id、stage（script/audio）、status（queued/running/succeeded/failed）、input_snapshot、error、result。脚本成功只表示脚本可审核，不表示音频完成。任务长耗时工作在后端运行；前端按编号查询，不能由前端计时器自行判定成功。只在实际分段数量可统计时显示百分比，否则显示阶段名。

这个demo尚未接入LLM，也没有脚本审核屏幕。相关接口可在技术负责人协调后增加：`POST /api/script-jobs`、`GET /api/script-jobs/{id}`；审核后音频任务接收`confirmed_script`。本demo仍用`text`直接合成，不能把后续接口草案当成已实现。

总结、周报和个人贡献：各自提供本人实际工作。小组评分按课程规则真实填写；讲评PPT由一人统稿，其他成员提供截图、测试结果和本人模块说明，建议由陈思涵组织、指定成员统稿，避免每人各做一套PPT。

## 从 demo 到正式项目的下一轮工作

- 第一轮：全员在自己电脑运行，互相说明一次上述五步，确认技术负责人及接口。
- 第二轮：谷优先验证真实语音及四种声音组合；李、吴完善页面；辜、周补数据库和任务机制；钱从第一轮就列用例。
- 第三轮：集成一次500字真实音频，再扩展至需求确认的篇幅、长文处理和错误场景。不要同时开始双人对话和受众改写。

本 demo 的500字限制用于快速理解流程，不能替代正式需求的5000字建议上限。没有登录、跨用户权限、数据库、长文分段、真实文件持久化、自动清理和完整部署能力。服务重启会清空内存任务；最多保留30个。仅绑定本机，不应直接用于公网。

## 可选：验证真实 Azure 语音

供应商只是可替换示例，不是已确定的技术选型。需要自行具备有效账户、区域、网络及额度；不要将密钥发到群聊或写入代码。以下命令仅在你明确打算调用真实服务时执行，可能计费。

PowerShell：
```powershell
$env:TTS_PROVIDER="azure"
$env:AZURE_SPEECH_REGION="你的区域"
$env:AZURE_SPEECH_KEY="你的密钥"
python server.py
```

真实模式会读取该区域支持的音色，根据中文、性别、cheerful或calm风格筛选。找不到支持组合时明确失败，不用默认音色假装实现。男声女声四种组合均需逐一实测，可能需要更换服务或经评审调整映射。真实模式返回MP3；离线模式返回WAV测试音。

**当前只验证了离线流程与服务失败处理；未使用真实账号验证Azure音质、风格或可用性。** 同文稿需人工核对漏读、数字英文、末尾完整性及风格差异。在线服务没有通过验证前，不能写入测试报告“真实合成通过”。

参考官方接口说明：https://learn.microsoft.com/en-us/azure/cognitive-services/speech-service/rest-text-to-speech

## 接口约定

提交请求：
```json
{"text":"要朗读的正文","gender":"female","style":"calm","speed":"normal"}
```

响应包含 `id` 和 `status`。状态为 `queued/running/succeeded/failed`；成功时含 `audio_url`、`extension`、`real_speech`；失败含 `error`。`input` 是该任务的参数快照。400表示输入无效，429表示已有任务进行中，404表示资源不存在，409表示音频未就绪。
