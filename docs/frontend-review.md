# TextCast 前端框架审核报告

## 审核结论

该工程的技术选型适合作为课程项目的前端基础，但原始交付状态不能直接作为团队主干或验收版本。审核中发现并修复了阻断解析、类型检查和构建的明确问题；修复后 TypeScript、Oxlint 和 Vite 构建均可执行。

建议“有条件采用”：保留现有页面布局、类型分层、请求封装、TanStack Query 和 MSW 基础，在同一仓库中继续开发；不要把当前 Mock 演示视为 FR01 至 FR12 已完成。合并真实后端前，应优先完成 FR11、FR12 的持久化流程、输入校验、两阶段任务模型以及真实音频下载。

## 技术结构评价

| 方面 | 结论 | 说明 |
| --- | --- | --- |
| React TypeScript Vite | 可采用 | 适合单页应用和课程演示，开发与构建链路清晰。 |
| TanStack Query | 可采用 | 已用于项目查询与缓存；写操作仍需统一改为 mutation 和缓存失效。 |
| MSW | 可采用 | 适合前后端并行开发，但当前 Mock 覆盖不完整且只保存在内存。 |
| API 与类型分层 | 基本可采用 | `api`、`types`、`mocks` 已分开；响应格式与生成任务契约还需统一。 |
| 页面组件 | 可继续拆分 | `Audio.tsx` 体积过大，项目页与脚本页仍混合临时状态更新和业务操作。 |
| 依赖管理 | 需收敛 | 同时声明不同主版本的 `react-router` 与 `react-router-dom`，并存在多个未使用依赖和误生成的根目录 `@` 文件夹。 |

## 非功能需求检查

- 构建与可移植性：锁文件存在，修复后可构建；已增加中文运行说明和 CI。建议在另一台电脑执行一次全新安装验证。
- 易用性：主要流程和状态徽标可理解，但全局搜索、通知、用户入口属于无实现的模板元素，容易误导，应移除或补齐。
- 无障碍：部分按钮有文字或 `aria-label`，但文件上传、范围输入、表格移动端显示和焦点流程仍需专门检查。
- 健壮性：网络错误有统一 `ApiError`，但项目创建、缓存写操作和下载失败的反馈不完整。
- 安全性：React 文本渲染未使用危险 HTML，前端环境文件也未发现密钥。真实服务密钥必须只保存在后端；下载不能接受任意文件路径。
- 性能：当前包体量可接受课程演示，但未进行路由懒加载；大型页面可后续拆分。LLM 和 TTS 性能必须分阶段记录。
- 测试：没有自动化单元、组件或端到端测试。CI 目前只能防止类型、Lint 和构建回归。

## 上线主干前的优先事项

1. 定义并实现 FR11 的脚本生成任务接口、状态、失败原因和重试。
2. 将项目重命名、原文保存、脚本保存、创建版本和确认全部改为真实 mutation，不再只修改前端缓存。
3. 完成 FR01/FR03 的文件、编码、长度和空白校验，并在后端重复校验。
4. 补齐试听 Mock、可播放示例音频，或在 Mock 模式明确禁用不可用功能。
5. 统一 `react-router` 依赖版本，删除未使用依赖和误生成目录。
6. 增加关键流程测试：未确认禁止生成、修改后重新确认、音频失败不重跑 LLM、版本快照保持一致。
7. 与后端确认统一错误响应、任务状态、下载响应和跨域策略。

## 推荐分工

- 前端 A：FR01 至 FR03 输入与校验、项目写操作。
- 前端 B：FR11 至 FR12 脚本任务、审核、版本与确认。
- 前端 C：FR04 至 FR10 声音、生成任务、播放器与下载。
- 后端联调负责人：维护接口契约、Mock 同步和错误码表。
- 测试负责人：维护需求矩阵、验收样例和关键状态转换测试。
